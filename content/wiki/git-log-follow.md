파일 하나의 커밋 이력을, 그 파일이 **이름이나 경로를 바꾸기 전의 이력까지 이어서** 보여주는 `git log` 옵션.

## 무엇인가

git 은 파일 이름 변경을 따로 기록하지 않는다. 커밋마다 트리 스냅샷만 있을 뿐이고,
"A 가 B 로 바뀌었다" 는 두 스냅샷의 내용 유사도로 **추론**된다(rename detection).
`--follow` 는 경로를 훑어 내려가다 파일이 사라지는 커밋에서 rename detection 을 돌려,
같은 내용을 가진 다른 경로로 추적 대상을 갈아탄다.

```bash
git log --follow -- path/to/file
```

## 구조

일반 경로 필터(`git log -- path`)는 리비전 목록 전체에 필터를 거는 방식이지만,
`--follow` 는 추적 대상 경로가 커밋을 따라 바뀌므로 **커밋을 순서대로 하나씩 흘려보내며**
경로를 갱신해야 한다. 이 차이가 아래 제약들을 만든다.

## 알아둘 것

- **경로 인자는 정확히 하나여야 한다.** 여러 경로나 디렉터리를 주면 동작하지 않는다.
- **`--reverse` 와 같이 쓰면 결과가 첫 커밋에서 잘린다.** 첫 커밋 하나만 출력되고 나머지가 사라진다.
  정렬은 호출하는 쪽에서 하는 편이 안전하다.
- rename detection 은 유사도 임계값(`-M`) 기반의 추론이다. 이름을 바꾸면서 내용을 크게 고치면 추적이 끊긴다.
- `git log --follow -p` 로 이름 변경 전 diff 까지 함께 볼 수 있다.
