값이 들어가는 자리가 HTML 본문인지, 속성인지, URL인지, 자바스크립트인지를 **파싱해서 판단하고**
그에 맞는 이스케이프를 자동으로 거는 Go 표준 템플릿 패키지.

## 무엇인가

`text/template` 과 문법은 같지만, 렌더 전에 템플릿을 파싱해 각 삽입 지점의 문맥을 분류한다.
같은 `{{ . }}` 라도 자리에 따라 다른 이스케이프가 걸린다.

| 자리 | 걸리는 이스케이프 |
| --- | --- |
| `<p>{{ . }}</p>` | HTML 본문 |
| `<a title="{{ . }}">` | HTML 속성 |
| `<a href="{{ . }}">` | URL |
| `<script>var x = {{ . }}</script>` | JS 리터럴 (문자열이면 따옴표까지 붙여준다) |
| `<style>{{ . }}</style>` | CSS |

이스케이프를 건너뛰려면 값을 `template.HTML`, `template.JS` 같은 타입으로 감싼다.
[[hugo]] 에서는 `safeHTML`, `safeJS`, `safeURL` 함수가 그 역할을 한다.

## 알아둘 것

- **속성 이스케이프 대상에 `+` 가 들어 있다.** `&#43;` 로 바뀐다. `<>&"'` 만 생각하면 놀란다.
  UTF-7 로 해석시키는 XSS 를 막는 방어적 처리다. → [[base64url]] 로 피한다.
- 백틱(`` ` ``)도 속성에서 이스케이프된다. IE 의 오래된 속성 파싱 때문이다.
- **`<script>` 안에서는 따옴표까지 붙여준다.** `var x = {{ .s }}` 가 `var x = "값";` 이 된다.
  여기에 `jsonify` 를 얹으면 따옴표가 두 겹이 된다. → [노트](/blog/notes/hugo-jsonify-in-script-double-quotes/)
- 브라우저는 속성을 읽을 때 엔티티를 되돌리므로 **런타임 동작은 멀쩡하다.**
  깨지는 건 렌더된 HTML 을 텍스트로 다시 파싱하는 쪽이다.
- 템플릿을 문자열로 조립해 넘기면 문맥 분석이 틀어질 수 있다. 구조는 템플릿에 두고 값만 넘긴다.
