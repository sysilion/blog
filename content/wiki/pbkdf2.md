비밀번호와 솔트를 받아 HMAC 을 정해진 횟수만큼 반복해서 고정 길이 키를 만들어내는 함수.
**일부러 느리게 만들어** 무차별 대입 비용을 올리는 게 존재 이유다.

## 무엇인가

```js
crypto.subtle.deriveKey(
  { name: 'PBKDF2', salt, iterations: 600000, hash: 'SHA-256' },
  material, { name: 'AES-GCM', length: 256 }, false, ['decrypt']
);
```

- **솔트** — 문서마다 다른 난수. 같은 비밀번호라도 결과 키가 달라져 미리 계산해둔 표(레인보우 테이블)를
  무력화한다. 비밀이 아니라 암호문 옆에 실어도 된다.
- **반복 횟수** — 방어자와 공격자 모두의 비용을 같은 비율로 올린다. OWASP 는 SHA-256 기준
  **60만 회**를 권한다. 최신 기기에서 1초 안팎이다.

## 알아둘 것

- 상대적으로 GPU·ASIC 에 유리한 알고리즘이다. 메모리를 거의 안 쓰기 때문이다.
  새로 설계한다면 **Argon2id** 나 **scrypt** 가 낫다. 다만 [[webcrypto]] 가 기본 제공하는 건 PBKDF2 뿐이라,
  라이브러리를 안 쓰려면 이걸 쓰게 된다.
- 반복 횟수는 암호문과 함께 저장해야 나중에 올릴 수 있다. 하드코딩하면 못 바꾼다.
- **정적 사이트에서는 암호문 자체가 공개된다.** 공격자가 오프라인에서 무한정 돌릴 수 있으므로
  60만 회로도 짧은 비밀번호는 못 지킨다. 단어 여러 개를 이은 긴 패스프레이즈를 쓴다.
