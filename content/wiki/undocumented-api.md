공식 문서가 없는, 웹·앱 클라이언트가 쓰는 내부 엔드포인트.
관측으로 동작을 알아내야 한다.

## 알아둘 것

**요청 파라미터가 계약이 아니다. 계약은 실제 응답이다.**
서버가 파라미터를 받기만 하고 쓰지 않는 경우가 흔하다. 공식 클라이언트가 늘 같은 값을 보내므로
서버 쪽에서 유효성을 지킬 이유가 없었을 뿐이다. `count=500` 을 보내도 200건이 오는 식이다.

관측한 값에 의존해야 할 때는 **그것이 관측값임을 코드에 남긴다.**

```python
# API가 count를 무시하고 실제로 반환하는 배치 크기 (진행률 추정용)
OBSERVED_BATCH_SIZE = 200
```

커서 페이지네이션도 신뢰하기 어렵다. **경계 항목이 다음 페이지에 다시 포함되는** 경우가 있어
중복 제거가 필수다. 값의 범위도 문서화된 가정과 다를 수 있다 — 음수 타임스탬프처럼.
