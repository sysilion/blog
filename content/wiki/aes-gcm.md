AES 를 카운터 모드로 돌려 암호화하면서 동시에 **인증 태그**를 만들어내는 모드.
기밀성과 무결성을 같이 준다. 이런 부류를 AEAD 라 부른다.

## 무엇인가

출력이 암호문 + 16바이트 인증 태그다. 복호화할 때 태그를 검증해서 어긋나면 **평문을 아예 내놓지 않고
실패한다.** 키가 틀렸는지, 누가 암호문을 건드렸는지를 구분하지 않고 똑같이 거부한다.

이 성질 덕에 비밀번호 확인용 해시를 따로 둘 필요가 없다. 복호화가 성공하면 그게 비밀번호가 맞다는 증거다.

[[webcrypto]] 에서는 태그가 암호문 뒤에 이어 붙은 형태를 기대한다.
Node 는 `getAuthTag()` 로 따로 주므로 이어붙여야 호환된다.

```js
// Node — 태그를 뒤에 붙인다
const ct = Buffer.concat([c.update(pt), c.final(), c.getAuthTag()]);

// 브라우저 — 그대로 넘기면 된다
await crypto.subtle.decrypt({ name: 'AES-GCM', iv }, key, ct);
```

## 알아둘 것

- **같은 키로 같은 IV(nonce) 를 두 번 쓰면 안 된다.** 평문이 복원 가능해지고 인증 키까지 샌다.
  12바이트 난수를 매번 새로 뽑는 게 표준 관행이다.
- IV 는 비밀이 아니다. 암호문 옆에 그대로 실어도 된다. 재사용만 안 하면 된다.
- 암호문 길이가 평문 길이를 그대로 드러낸다. 스트림 암호라 패딩이 없다.
- 비밀번호를 바로 키로 쓰면 안 된다. [[pbkdf2]] 같은 키 유도 함수를 거친다.
