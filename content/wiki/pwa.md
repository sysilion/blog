일반 웹 페이지에 설치·오프라인 동작·푸시 알림 같은 네이티브 앱의 성질을 얹은 웹 앱. 별개 기술이 아니라 **웹 앱 매니페스트 + [[service-worker|서비스 워커]] + HTTPS** 세 요건을 갖춘 사이트를 부르는 이름이다.

## 구조

| 요건 | 역할 |
| --- | --- |
| `manifest.webmanifest` | 이름·아이콘·시작 URL·표시 모드(`standalone`)·테마색. 홈 화면 설치 정보 |
| 서비스 워커 | 요청 가로채기·캐시·백그라운드 동기화·푸시 수신. 오프라인의 본체 |
| HTTPS | 서비스 워커·푸시·설치 프롬프트가 [[secure-context|보안 컨텍스트]] 에서만 동작한다 |

설치되면 브라우저 UI 없이 독립 창으로 열리고, OS 앱 목록에 들어간다. Android는 Chrome이 WebAPK로 감싸고, iOS는 Safari의 "홈 화면에 추가"로 설치된다.

## 알아둘 것

- **`localhost` 는 HTTPS 없이도 보안 컨텍스트다.** 그래서 개발 서버에서는 잘 되던 서비스 워커가 LAN IP나 사설 도메인으로 접근하면 등록조차 안 된다. 실기기 테스트는 HTTPS를 붙이거나 터널을 써야 한다.
- **서비스 워커는 빌드 산출물에서 확인해야 한다.** 개발 서버(vite dev 등)는 워커를 주입하지 않거나 다르게 다룬다. `vite preview` 같은 산출물 서빙으로 봐야 실제 동작이 보인다.
- **iOS 제약이 크다.** 웹 푸시는 iOS 16.4부터 홈 화면에 설치된 PWA에만 허용된다. 백그라운드 실행·정확한 시각 알람은 불가하다. 알람 앱 같은 것은 앱이 포그라운드에 있을 때만 확실히 동작한다고 봐야 한다.
- 서비스 워커의 캐시 전략이 곧 업데이트 정책이다. `skipWaiting` 없이는 모든 탭이 닫힐 때까지 새 버전이 활성화되지 않는다.
- 설치 프롬프트(`beforeinstallprompt`)는 Chromium 계열에만 있다. Safari·Firefox에는 프로그램적 설치 유도가 없다.
