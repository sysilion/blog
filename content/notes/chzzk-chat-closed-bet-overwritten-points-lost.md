## 무슨 일이

chzzk-chat 관리 패널에 승부예측 조작 버튼을 붙이려고 `!배팅시작` 핸들러를 메서드로 옮기다가 발견했다.
`!배팅종료`로 마감한 뒤 `!결과`를 내지 않고 `!배팅시작`을 다시 치면 새 라운드가 열렸다.
이전 라운드에서 차감한 포인트는 돌려주지도, 정산하지도 않은 채 사라졌다.

## 원인

배팅 포인트는 참여 순간 차감되고 정산 때까지 라운드 맵에만 기록된다. [[escrow|에스크로]]처럼
라운드가 포인트를 쥐고 있는 구조다. 그런데 중복 시작 검사가 이렇게 생겼다.

```go
if r, ok := bm.rounds[ctx.ChannelID]; ok && r.Open { /* 거부 */ }
bm.rounds[ctx.ChannelID] = &BetRound{ /* ... */ } // 마감된 라운드는 그대로 덮어씀
```

`r.Open`이 false인 '마감, 정산 전' 상태를 빠뜨렸다. 거부 문구도 "!배팅종료 또는 !결과 로 먼저
마무리하세요"여서 `!배팅종료`만 쳐도 마무리된 것처럼 읽혔다.

## 재현

수정 전 코드에서 아래 테스트가 실패한다. 수정 후 `internal/bot/control.go`의 `Open`은 라운드가
남아 있으면 상태와 관계없이 거부한다.

```bash
cd chzzk-chat
go test ./internal/bot -run TestBetOpenRejectsWhileUnresolvedRoundExists -v
```

같은 구조 탓에 정산 전 라운드가 있을 때 프로세스를 재시작해도 차감된 포인트가 사라진다.
라운드가 메모리에만 있어서다. 이건 아직 고치지 않았다.

## 그래서

열기 조건을 "라운드 없음"으로 바꾸고, 마감된 라운드가 있으면 `!결과` 또는 `!배팅취소`로 끝내라고 안내한다.
관리 패널과 채팅 명령어가 같은 `BetManager.Open`을 거치도록 묶었다.

## 한 줄

값을 미리 빼 두는 기능을 고칠 때는 그 값을 쥔 객체를 덮어쓰거나 버리는 경로부터 찾는다.
