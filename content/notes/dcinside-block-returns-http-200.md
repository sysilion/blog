## 무슨 일이

요청 간격이 짧으면 디시가 [[bot-detection|차단]]하는데, **HTTP 상태 코드는 200**이다. 본문이 빈 응답이거나
`정상적인 접근이 아닙니다` 텍스트다. `resp.StatusCode`만 보는 코드는 차단을 정상 응답으로
받아 빈 결과를 파싱한다.

## 원인

차단 처리가 웹 서버 계층이 아니라 애플리케이션 페이지 계층에 있다. 브라우저에 안내 화면을
보여주는 것이 목적이라 상태 코드를 바꿀 이유가 없다.

## 그래서

**본문을 보고 판정**한다. 그리고 차단은 두 종류로 나뉜다.

```go
// 요청 간격/세션 문제
var ErrBlocked = errors.New("dcinside: 비정상 접근으로 차단됨 (요청 간격을 늘려보세요)")

// IP 차단 — 해제 시각이 메시지에 들어 있다
var reIPBlockUntil = regexp.MustCompile(
    `사용\s*가능\s*시간은?\s*(\d{4}[/-]\d{1,2}[/-]\d{1,2}[\sT]+\d{1,2}:\d{2}(?::\d{2})?)`)
```

실제로 받은 메시지는 이런 형태다.

```text
[기타 :  ] 사유로 차단당한 IP입니다.사용가능시간은2026/08/12 18:13:07
[기타 : 비정상 글쓰기 시도] 사유로 차단된 IP입니다.
```

해제 시각을 파싱해 두면 `RetryAfter()`로 정확히 그만큼만 자면 된다. 감으로 재시도하는 것보다
낫다. 공백이 없는 `시간은2026/...`까지 커버해야 해서 정규식에 `\s*`가 들어간다.

세션 쿠키가 없을 때도 같은 문구가 온다. 댓글 API는 글 본문 페이지에서 발급된 세션 쿠키를
요구하므로, `Client`를 재사용하지 않고 요청마다 새로 만들면 계속 차단으로 보인다.

## 한 줄

> 상태 코드를 신뢰할 수 없는 API에서는 **본문이 곧 상태 코드**다.
