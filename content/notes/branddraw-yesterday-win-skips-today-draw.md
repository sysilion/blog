## 무슨 일이

[[브랜드뽑기]] 자동 실행은 매일 13:57 에 창을 띄우고 14:00 오픈을 기다리게 해뒀다.
그런데 오늘(2026-09-18) 리포트가 이렇게 남았다.

```json
{ "timestamp": "2026-09-18T13:57:14", "duration_sec": 8.4,
  "result": "이미참여", "brand_name": "오늘의집", "brands": [] }
```

8.4초. 오픈을 기다리지도 않고 끝났다. '오늘의집' 은 **어제** 뽑은 브랜드다.

## 원인

당첨은 뽑은 날로 끝나지 않는다. 응답의 `eventEndDate` 가 **익일 14:00** 이다.

```
{"brandName": "오늘의집", "eventEndDate": "2026-09-18T14:00:00"}   ← 9/17 에 뽑은 것
```

그래서 다음날 13:57 에 페이지를 열면 서버가 아직 `apply` 를 주고, 페이지는
`/npay/branddraw/apply/` 로 튕긴다. 그 경로를 보고 이렇게 끝내버린 것이 문제였다.

```python
if st["path"].rstrip("/").endswith(("/apply", "/winner")):
    return st                       # 이미 참여한 상태로 튕겨짐
```

`/apply/` 는 '오늘 이미 뽑았다' 가 아니라 '**직전 당첨이 아직 유효하다**' 는 뜻이다.
14:00 이 되면 풀린다. 과거 리포트도 같은 모양이었는데 그때는 원인을 몰랐다.

| 실행 | 결과 | 브랜드 | 실제로 뽑은 날 |
| --- | --- | --- | --- |
| 09/11 13:57 | 이미참여 | 코레일 | 09/10 |
| 09/15 13:57 | 이미참여 | 알라딘 | 09/14 |
| 09/18 13:57 | 이미참여 | 오늘의집 | 09/17 |

즉 **뽑는 날 다음날은 반드시 건너뛴다.** 격일로만 참여하고 있었던 셈이다.

## 재현

```bash
cd ~/proj/naver
cat reports/branddraw_2026-09-18_13-57-14.json     # duration 8.4초, brands 비어 있음
```

## 그래서

오픈 전이면 기다렸다 다시 열게 했다. 14:00 에 상태가 풀리는 걸 전제로 한다.

```python
if st["path"].rstrip("/").endswith(("/apply", "/winner")):
    if datetime.now() < open_at and not revisited:
        revisited = True
        _sleep_until(open_at)                      # +2초 여유
        page.goto(cfg.branddraw.page_url, ...)
        continue
    return st
```

- 오픈 이후의 판정은 그대로다 — 16:15 에 돌려 4초 만에 `이미참여` 로 끝나는 것을 확인했다.
- 하루를 놓친 김에 16:04 에 손으로 돌려 보너스 뽑기로 올리브영을 받았다. 선착순은
  이미 전부 마감이었다.
- `mode` 도 `observe` → `pick` 으로 바꿨다. 고쳐도 관찰만 하면 뽑지 않는다.
