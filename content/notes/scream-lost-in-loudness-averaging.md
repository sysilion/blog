## 무슨 일이

chicle의 🔊 큰 소리 검출이 6시간 방송(15762153)의 4:25:02 비명을 놓쳤다.
같은 오디오를 0.1초 단위로 다시 재 보니 신호 자체는 아주 컸다.

| 단계 | 비명 순간의 상승폭 |
| --- | --- |
| 0.1초 [[rms\|RMS]] | +23.5 dB |
| 0.1초 1~4kHz 대역 에너지 | +36.3 dB |
| 1초 RMS (현재 측정 단위) | +12.6 dB |
| 1초 RMS + 3초 이동평균 (현재 후보 점수) | +4.2 dB |

후보 기준선은 상위 1%인 5.69dB였다. 이보다 시끄러운 초가 1,416초나 됐다.

## 원인

비명이 0.3초 남짓이라 평균 창에 들어가면 나머지 무음·말소리와 섞여 희석된다.
창이 1초→3초로 두 번 겹치면서 20dB 가까이 깎였다. 반면 BGM·게임 효과음처럼
계속 큰 소리는 평균을 내도 줄지 않아 순위를 가져간다.

## 재현

```python
import numpy as np
# rms_db: 0.1초 프레임 RMS(dBFS), band_db: 같은 프레임의 1~4kHz 에너지 (16kHz mono FFT)
per_sec_max = lambda x: x.reshape(-1, 10).max(1)
sustain = lambda x: np.minimum(np.minimum(x, np.roll(x, 1)), np.roll(x, 2))  # 0.3초 유지
score = per_sec_max(sustain(band_db - np.median(band_db[rms_db > -80])))
# 60초 간격으로 피크를 고르면 15902초(비명)가 2위. 현재 방식은 40위 밖.
```

| 점수 | 비명 순위 |
| --- | --- |
| 현재: 1초 RMS + 3초 평균 | 40위 밖 |
| 0.1초 RMS의 초당 최댓값 | 16위 |
| 1~4kHz 대역, 0.3초 지속, 초당 최댓값 | 2위 |

## 그래서

- 짧은 반응은 창 안의 최댓값으로 본다. 대신 0.3초 이상 유지 조건으로 클릭·타격음을 거른다.
- 음량보다 대역이 더 잘 가른다. 비명은 1~4kHz에 몰리고, 방송 오디오는 컴프레서가 전대역 크기를 눌러 둔다.
- 0.1초로 재도 시간은 거의 같다. 병목은 다운로드다 (6시간 VOD 12분, 기존 1초 측정과 비슷).

## 한 줄

짧은 소리를 찾는 검출기는 이동평균부터 걷어내고, 창 안의 최댓값에 지속 시간 조건을 붙여 본다.
