## 무슨 일이

T멤버십 앱에서 출석체크를 자동화하는데, 매번 아이폰 사전예약 **광고 페이지**가 열렸다.
로그를 보면 제대로 찾아서 눌렀다.

```
탭 Node('출석체크' @901,1305)
→ 결과: 다른 앱이 전면입니다 (com.sec.android.app.sbrowser/.SBrowserMainActivity)
```

## 원인

[[uiautomator]] 덤프를 뜨면 전면 팝업과 **그 아래 화면이 함께** 나온다.

```
[0,0][1080,2640]      View    'club iPhone 18 Pro 사전 예약 즉시 혜택 ...'   ← 화면 전체를 덮은 팝업
[898,1245][1004,1365] View    '출석체크'                                    ← 그 아래 홈의 메뉴
[637,1758][987,1900]  Button  '닫기'
```

`출석체크` 노드는 분명히 트리에 있고 좌표도 정확하다. 하지만 그 위에 팝업이 있으므로
그 좌표를 누르면 **팝업이 눌린다.** 접근성 트리는 z-order 를 알려주지 않는다.

여기에 타이밍이 겹쳤다. 이 팝업은 홈이 그려지고 **몇 초 뒤에** 뜬다. 진입 직후
덤프에는 없어서 "팝업 없음" 으로 판단하고 진행하는데, 누르는 순간엔 이미 떠 있다.

## 그래서

두 가지를 같이 해야 막힌다.

**누르기 전에 닫는다.** 닫을 게 없으면 즉시 돌아오므로 손해가 없다.

**누른 뒤에 확인한다.** 대상 앱을 벗어났으면 탭을 빼앗긴 것이다. 돌아와서 닫고 한 번 더.

```python
A.dismiss_popups(POPUP_CLOSE, rounds=2)
entry = A.wait_text("출석체크", 30)
A.tap_node(entry)

if not A.in_foreground(package):        # 팝업이 가로챘다
    A.launch(package)
    A.wait_activity(package, 30)
    A.dismiss_popups(POPUP_CLOSE, rounds=2)
    A.tap_node(A.wait_text("출석체크", 30))
```

## 덤으로 — 성공도 같은 이유로 놓친다

출석에 성공하면 보상 팝업이 뜨는데, 이때는 반대로 트리가 **노드 4개로 줄었다.**
뒤에 있던 '출석체크 완료' 가 통째로 사라져서, 버튼 상태로 성공을 재던 판정이
'눌렀지만 완료 표시를 확인하지 못함' 으로 끝났다. 실제로는 적립된 뒤였다.
팝업 문구(`룰렛 1회`) 자체를 성공 신호로 쓰는 편이 확실하다.

같은 트리가 어떨 땐 아래를 다 보여주고 어떨 땐 덮개만 보여준다. 덮개가 앱의 뷰인지
웹뷰인지에 따라 다르다.

## 한 줄

트리에 있다고 누를 수 있는 게 아니다. 누른 뒤에 어디에 있는지 확인해야 안다.
