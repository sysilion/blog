## 무슨 일이

클라우드 LLM으로 나가는 텍스트에서 개인정보를 가리는 층을 만들었다. 전화번호 패턴을
이렇게 썼다.

```rust
static PHONE: LazyLock<Regex> = LazyLock::new(|| {
    Regex::new(r"(?:\+?82[\s\-]?)?0?1[0-9][\s\-.]?\d{3,4}[\s\-.]?\d{4}\b").unwrap()
});
```

테스트가 하나 깨졌다.

```
left:  "010-1234-5678로 연락"
right: "[전화번호]로 연락"
```

`"010-1234-5678"` 단독은 잡힌다. 뒤에 조사 `로`가 붙으면 못 잡는다.

## 원인

[[regex-crate|regex]] 크레이트는 기본이 유니코드 모드다. `\b`는 **유니코드 단어 경계**이고,
`\w`에 해당하는 문자 집합은 ASCII 영숫자가 아니라 유니코드 속성 `Word`다.
**한글은 `Word` 문자다.**

그래서 `5678로` 의 `8`과 `로`는 **둘 다 단어 문자**다. 경계가 서지 않는다.

같은 이유로 앞쪽 `\b`도 문제가 된다. `주민번호는900101-1234567` 에서 `는`과 `9` 사이에도
경계가 없다. 영어 문장에서는 거의 드러나지 않고 한국어에서만 터진다 — 조사가 숫자에
곧바로 붙기 때문이다.

## 재현

```rust
use regex::Regex;

fn main() {
    let uni = Regex::new(r"\d{4}\b").unwrap();
    let ascii = Regex::new(r"\d{4}(?-u:\b)").unwrap();

    println!("{:?}", uni.find("5678로"));    // None
    println!("{:?}", ascii.find("5678로"));  // Some(0..4)
    println!("{:?}", uni.find("5678 로"));   // Some(0..4)  ← 띄우면 잡힌다
}
```

## 그래서

`(?-u:\b)` 로 그 자리만 ASCII 단어 경계로 낮춘다. 숫자는 ASCII 단어 문자, 한글은 아니므로
둘 사이가 경계가 된다.

```rust
fn re(pattern: &str) -> Regex { Regex::new(pattern).expect("pattern") }

static PHONE: LazyLock<Regex> = LazyLock::new(|| {
    re(r"(?:\+?82[\s\-]?)?0?1[0-9][\s\-.]?\d{3,4}[\s\-.]?\d{4}(?-u:\b)")
});
```

`(?-u:...)` 는 그 그룹 안에서만 유니코드 모드를 끈다. 영점폭 단언이라 "UTF-8이 아닌 것을
매치할 수 있다"는 컴파일 오류도 나지 않는다 — `(?-u:.)` 나 `(?-u:\w)` 같은 **문자 클래스**를
비유니코드로 쓸 때만 그 오류가 난다.

패턴에 `\b`를 쓰는 자리가 여럿이면 전부 바꿔야 한다. 주민번호·카드번호·IP 패턴이 전부
같은 함정에 걸려 있었다.

## 한 줄

한국어 텍스트에서 숫자 패턴을 잡을 거면 `\b`가 아니라 `(?-u:\b)` 다.
