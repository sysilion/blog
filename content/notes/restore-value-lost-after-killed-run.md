## 무슨 일이

앱 출석체크는 도는 동안만 폰의 화면 꺼짐 시간을 30초에서 5분으로 늘리고, 끝나면
되돌린다. 그런데 실행이 끝난 뒤에도 폰이 5분으로 남아 있었다. 로그에는 이렇게 찍혀 있었다.

```
화면 꺼짐 300000ms → 300000ms (끝나면 되돌림)
화면 꺼짐 복원: 300000ms
```

"복원" 은 제대로 돌았다. 다만 **되돌린 값 자체가 틀렸다.**

## 원인

두 가지가 겹쳤다.

1. 앞선 실행을 `timeout 300` 으로 돌렸다가 [[sigterm|SIGTERM]] 으로 끊겼다. 파이썬은
   SIGTERM 핸들러가 없으면 `finally` 없이 그냥 죽는다. 그래서 5분이 남았다.
2. 다음 실행은 그 5분을 **원래 값으로 읽었다.** 그리고 새 워치독을 걸면서 앞선 실행의
   기기 쪽 워치독(30분 뒤 30000 으로 되돌릴 예정이던 것)을 꺼 버렸다. 30000 이라는
   값은 이 순간 어디에도 남지 않게 됐다.

```python
# 재현 — 핸들러 없는 SIGTERM 에서는 finally 가 돌지 않는다
import time
try:
    time.sleep(30)
finally:
    print("restored")     # kill -TERM <pid> 이면 안 찍힌다
```

## 그래서

- 원래 값을 기기 파일(`/data/local/tmp/naverpay_awake_prev`)에 적어 두고, 복원을 끝내야
  지운다. 다음 실행은 이 파일이 있으면 지금 값 대신 이 값을 원래 값으로 쓴다.
- `keep_awake` 에 SIGINT·SIGTERM 핸들러를 걸어 `KeyboardInterrupt` 로 바꾼다. 그러면
  `finally` 로 가서 되돌린다.

실기기에서 확인했다. SIGTERM 을 받으면 30000 으로 복원됐다. 되돌림 없이 죽은 뒤에는
파일에 30000 이 남았고, 다음 실행이 그 값을 이어받아 30000 으로 복원한 뒤 파일을 지웠다.

## 한 줄

설정을 잠시 바꿨다가 되돌리는 코드는, 원래 값을 **바꾸기 전에 어딘가에 남겨야** 한다.
지금 값은 앞선 실행이 남긴 흔적일 수 있다.
