## 무슨 일이

LumiaLore 설계 저장소의 참고 자료 조사로 [[worldclaw]] 논문(arXiv:2608.05248, 2026-08-05)을 읽었다.
"텍스트 프롬프트 하나로 걸어다닐 수 있는 3D 오픈월드를 만든다"는 논문인데,
읽고 나니 **3D 생성 논문이 아니라 에이전트 파이프라인 설계 논문**이었다.

## 핵심

월드를 한 번에 생성하지 않는다. LLM 에이전트 여럿이 [[coarse-to-fine]]으로 세 단계를 잇고,
단계 사이는 자유 텍스트가 아니라 **구조화된 사양**으로 통신한다.

```text
P = F_plan(q)          # 프롬프트 → 씬 사양 (지역·지형·오브젝트·재료·관계)
T = F_terrain(P)       # 사양 → 전역 지형 (시맨틱 레이아웃 맵 → 높이 필드)
O = F_region(P, T)     # 사양 + 지형 → 디테일이 필요한 지역만 오브젝트 생성·배치
S = Compose(T, O)
```

- **계획**: "사용자가 말한 것만 뽑는" 의도 분석 에이전트와 "스키마대로 빈칸을 채우는" 씬 계획 에이전트를 **따로** 둔다. 의도 보존과 정보 보완은 실패 양상이 달라서다.
- **지형**: 지형 카테고리를 색으로 칠한 레이아웃 맵을 이미지 모델로 만들고, 지역별 기준 고도 + 노이즈 + 지형 연산자를 가중합해 한 장의 연속 지형을 만든다. 바위·식생처럼 반복되는 것은 프로토타입 하나를 산포한다.
- **지역**: 지형을 렌더한 위에 이미지 편집 모델로 오브젝트를 그려 넣고(2D 레이아웃 프라이어), [[sam-3]]로 인스턴스를 떼어 메시로 복원한 뒤, 카메라 레이 대응으로 3D 위치·스케일을 되찾는다. 논문의 기술적 기여는 이 배치 복구 수식이다.
- **정제**: [[blender-mcp]]로 Blender에 붙어 렌더 → 검사 → 국소 수정 루프를 돈다. 종료 조건은 **"문제 없음 또는 반복 예산 소진"** 둘 다. 수정 범위는 접촉 부위로 제한해 전역 구조를 지킨다.

부품은 Claude Opus 4.8(에이전트), GPT-Image-2(이미지), SAM 3/SAM 3D(분할·복원), [[hunyuan3d]](3D 자산), Blender 5.1.1.

## 확인한 것

저장소에는 README와 그림만 있다. 코드·가중치·라이선스가 없다.

```bash

# .gitignore  README.md  assets
gh api repos/Tencent-Hunyuan/Hunyuan3D-WorldClaw --jq '.license'

```

평가도 정성 비교만 있다. 비교 대상은 [[worldgen]], Marble, SynCity, MajutsuCity, 코딩 에이전트 단독(GPT-5.6 Sol).
저자 스스로 한계로 적은 것: 오픈소스 LLM은 실행 가능한 절차적 지형·재료 코드를 잘 못 만들었고,
오픈소스 이미지 모델은 쓸 만한 레이아웃 맵을 잘 못 만들었다. 오브젝트를 개별 생성하고 정제를 여러 번 돌아 느리고 비싸다.

## 그래서

3D 자산 생성은 LumiaLore의 범위가 아니다. 가져갈 것은 파이프라인 패턴이다.

1. **명시 추출과 스키마 보완을 다른 에이전트로 분리**한다. 기획 문서 → 구조화 사양 변환에 그대로 쓸 수 있다.
2. **에이전트 사이는 스키마로 잇고 전역 속성은 상속**시킨다.
3. **정제 루프는 이중 종료 조건 + 국소 수정.** 자동화 폭주를 막는 가장 싼 장치다.
4. **전역 제약 먼저, 디테일은 필요한 곳만.** 월드·지역 설계 문서의 계층과 같다.
5. **재사용 프로토타입과 정체성 있는 인스턴스를 구분**한다.

반면 논문의 품질 주장과 "오픈소스로는 안 됐다"는 관측은 근거로 인용하지 않는다. 정량 지표가 없고, 2026년 상반기 저자 환경에 한정된 얘기다.

부품은 전부 공개돼 있다 — [[hunyuanworld]], WorldGen, BlenderMCP, Hunyuan3D, SAM 3. 논문 2장이 설계 명세 역할을 하므로 재현 실험은 지금도 가능하다.

## 한 줄
