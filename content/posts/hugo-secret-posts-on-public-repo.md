블로그에 비밀글을 붙이고 싶었다. 비밀번호를 아는 사람만 읽는 글.

이 블로그는 Hugo 로 빌드해 GitHub Pages 로 배포한다. 정적 호스팅이라 **서버가 요청자를 확인할
방법이 없다.** 로그인도, 세션도, 접근 제어도 없다. 파일을 달라고 하면 준다. 그게 전부다.

그러면 방법은 하나뿐이다. **암호화된 채로 내주고, 브라우저에서 푼다.**

## 기성 도구는 왜 못 썼나

[[hugo]] 용 도구는 이미 여럿 있다. StatiCrypt, hugo-encrypt, hugo_enc, HugoMods 의 encrypt 모듈.
넷 다 [[aes-gcm]] 으로 제대로 암호화하고 [[webcrypto]] 로 브라우저에서 푼다. 암호학적으로 멀쩡하다.

그런데 하나도 쓸 수 없었다. **전부 빌드 후 처리**이기 때문이다.

```
content/*.md (평문) → hugo → public/*.html (평문) → CLI 가 걸어다니며 암호화
```

암호화 대상이 `public/` 이다. 원문 마크다운은 `content/` 에 평문으로 남고, 그게 커밋된다.
HugoMods 문서는 이걸 대놓고 적어둔다 — 저장소를 private 으로 유지하라고.

이 도구들이 지키는 건 **배포된 사이트를 우연히 방문한 사람**이지, 저장소를 볼 수 있는 사람이
아니다. 내 저장소는 public 이다. 자물쇠 옆에 열쇠를 붙여두는 꼴이 된다.

## 평문을 저장소 밖으로

그래서 방향을 뒤집었다. **빌드 후가 아니라 커밋 전에 암호화한다.**

```
secret-src/<slug>.md          평문. .gitignore — 저장소에 절대 안 들어간다
     ↓ content/secretbuild/ 로 옮겨 hugo 로 렌더
     ↓ AES-256-GCM 암호화
content/secret/<slug>.md      암호문 스텁. 이것만 커밋된다
     ↓ 브라우저에서 복호화
```

평문은 `secret-src/` 에만 있고 gitignore 다. 커밋되는 건 암호문뿐이다. GitHub Actions 는
이미 암호화된 스텁을 평소대로 빌드한다 — **CI 는 비밀번호를 알 필요가 없다.** 배포 설정을
건드리지 않아도 됐다.

### 왜 마크다운이 아니라 렌더된 HTML 을 암호화하나

처음엔 마크다운을 그대로 암호화하고 브라우저에서 마크다운 렌더러를 돌릴까 했다. 간단하다.
그런데 그러면 **이 블로그의 고유한 것들이 전부 죽는다.** 위키링크 `[[...]]` 는 Hugo 템플릿에서
후처리하고, 코드 하이라이트는 Chroma 가 빌드 시점에 만든다. 브라우저 렌더러는 둘 다 모른다.

그래서 렌더를 한 번 거친다. 평문을 임시로 `content/secretbuild/` 에 넣고 Hugo 를 돌려
**본문 HTML 만 뱉는 전용 레이아웃**으로 받는다.

```go-html-template
{{- /* layouts/secretbuild/single.html
       define 블록이 없으므로 baseof 를 타지 않는다 → 본문 HTML 만 남는다 */ -}}
{{- partial "wiki/render.html" .Content | safeHTML -}}
```

덕분에 비밀글 안에서도 `[[apfs]]` 가 진짜 위키 링크가 되고, 코드 블록에 하이라이트가 붙는다.
공개 글과 **같은 파이프라인을 통과한 결과물**을 암호화하는 셈이다.

### 원문도 같이 넣는다

암호문 안에 들어가는 건 셋이다.

```js
{ title, html, source }
```

`source` 가 원본 마크다운이다. 이게 있으면 **새로 클론한 곳에서도 비밀번호만으로 편집 가능한
원문이 돌아온다.**

```bash
git clone ...
node scripts/secret.mjs restore   # 비밀번호 → secret-src/*.md 가 되살아난다
```

평문을 저장소 밖에 두면 백업이 사라지는 게 문제인데, 이걸로 **저장소 자체가 암호화된 백업**이
된다. 대신 성질이 하나 바뀐다 — 비밀번호를 잃으면 원문도 같이 잃는다. 예전엔 평문이라도
남았지만 이젠 암호문이 유일본이다.

## 비밀번호는 한 번만

처음엔 글마다 솔트를 따로 뽑았다. 안전하지만 쓸 수가 없었다. 글을 옮길 때마다
[[pbkdf2]] 60만 회를 다시 돌리고 비밀번호를 다시 쳐야 한다.

그래서 **사이트 전체가 키 하나를 공유**하도록 바꿨다. 솔트는 한 벌만 둔다.

```json
// data/secret.json — 비밀이 아니다. 커밋된다.
{ "v": 1, "iter": 600000, "salt": "...", "check_iv": "...", "check_ct": "..." }
```

솔트를 숨겨서 얻는 건 없다. 솔트의 일은 **미리 계산해둔 표를 무력화하는 것**이지 비밀 유지가
아니다. `check_ct` 는 알려진 문자열("secret-ok")을 암호화해 둔 것이고, 이게 풀리면 키가 맞다는
뜻이다. 덕분에 목록 페이지처럼 풀 게 없는 화면에서도 비밀번호를 즉시 판정할 수 있다.

키를 공유하되 **IV 는 글마다 새로 뽑는다.** 같은 키로 IV 를 재사용하면 GCM 은 무너진다.
평문이 복원 가능해지고 인증 키까지 샌다. 이건 타협할 수 있는 부분이 아니다.

유도한 키는 `sessionStorage` 에 둔다. 탭을 닫으면 사라진다. '30일 기억' 을 고르면
`localStorage` 로 간다. 어느 쪽이든 이 브라우저 밖으로 나가지 않는다.

```js
// 비밀번호 → 키. 검증값이 풀려야 통과시킨다.
crypto.subtle.deriveBits(
  { name: 'PBKDF2', salt: bytes(CFG.salt), iterations: CFG.iter, hash: 'SHA-256' },
  material, 256
)
```

`deriveKey` 가 아니라 `deriveBits` 를 쓴 건 **원시 바이트를 꺼내 저장해야** 하기 때문이다.
`deriveKey` 로 만든 키는 `extractable: false` 면 꺼낼 수 없고, 꺼낼 수 있게 만들면 굳이
`deriveKey` 를 쓸 이유가 없다.

### 목록에서는 제목만 푼다

잠긴 목록에 "비밀글" 만 여섯 줄 늘어서면 쓸모가 없다. 그렇다고 목록에서 본문 전체를 받아
푸는 건 낭비다. 그래서 **제목을 본문과 따로 한 번 더 암호화**해 스텁에 넣는다.

```yaml
secret_iv: "..."          # 본문
secret_ct: "..."
secret_title_iv: "..."    # 제목만
secret_title_ct: "..."
```

잠겨 있으면 `🔒 비밀글`, 풀면 그 자리에 진짜 제목이 채워진다.

## 새는 곳 막기

암호화만으로는 부족하다. 암호문 주변에 붙는 것들이 샌다. 하나씩 확인하며 막았다.

**사이트 전체 수집.** 스텁이 홈·아카이브·검색 인덱스·RSS 에 그대로 올라간다. 특히 RSS 가
제목과 날짜와 URL 을 실어 보내고 있었다.

```yaml
build:
  list: local     # 자기 섹션 목록에만. 사이트 전체 수집에서는 빠진다
searchHidden: true
ShowToc: false    # 목차는 제목들을 그대로 드러낸다
```

섹션 자체의 RSS 도 `outputs: ["HTML"]` 로 없앴다.

**URL.** 이게 제일 컸다. 파일명이 곧 URL 이다. 사건을 서술하는 평소 작명 규칙
(`<서비스>-<무엇이-어떻게>.md`) 을 그대로 두면 목록에 제목이 "비밀글" 이어도 **링크 주소가
전부 말해준다.** 숨기려던 게 주소창에 적혀 있는 셈이다. `secret-01` 같은 중립적인 slug 로
바꿔야 했다. 원래 제목은 어차피 암호문 안에 들어 있으니 잃는 것도 없다.

**태그와 요약.** 스텁에 옮기지 않는다. 태그를 남기면 태그 페이지가 생기고, 요약은 목록에 그대로 뜬다.

## 걸린 것들

구현하면서 네 번 막혔다. 전부 암호 쪽이 아니라 Hugo 와 Go 템플릿 쪽이었다.

**`--buildDrafts` 는 미래 날짜 글을 포함하지 않는다.** 렌더 결과가 없다며 죽길래 한참 봤는데,
프론트매터 날짜가 27분 뒤였다. `buildFuture` 는 별개 스위치이고 `-F` 다. 에러도 경고도 없이
그냥 페이지가 없다.

**Go 가 속성 안의 `+` 를 `&#43;` 로 바꾼다.** base64 를 `data-*` 속성에 실었더니 그렇게 됐다.
[[html-template]] 의 속성 이스케이프 대상에 `+` 가 들어 있다 — UTF-7 XSS 방어다. 브라우저는
엔티티를 되돌려 읽으므로 동작은 멀쩡했지만, 빌드 결과를 텍스트로 파싱하는 검증 스크립트가
깨졌다. [[base64url]] 로 바꿔 피했다.

**`_build` 프론트매터 키는 Hugo 0.145 에서 제거됐다.** `build` 로 바뀌었다. 무시가 아니라
`ERROR` 로 빌드가 exit 1 한다. 오래된 예제는 아직 전부 `_build` 다.

**`<script>` 안에서 `jsonify` 를 쓰면 따옴표가 두 겹이 된다.** 이게 제일 고약했다. 맞는
비밀번호를 넣었는데 계속 "비밀번호가 틀렸다" 가 떴다. 원인은 솔트였다.

```js
salt: "\"3CEYiqtk5vVzkcaJpnSatA\"",   // {{ .salt | jsonify }}
```

html/template 은 삽입 지점이 자바스크립트라는 걸 알면 **따옴표까지 직접 붙여준다.** `jsonify`
가 이미 따옴표를 포함한 문자열을 넘기니 한 겹이 더 씌워졌다. 솔트가 달라지고 → 키가 달라지고
→ GCM 인증이 실패하고 → "비밀번호가 틀렸다". **암호 코드는 멀쩡했고 문자열 한 겹이 문제였다.**

## 잊어버리는 것 막기

다 만들고 나니 구멍이 하나 남았다. **평문을 고치고 재암호화를 잊으면 아무 신호도 없다.**

`secret-src/` 는 gitignore 라 `git status` 에 안 뜬다. Hugo 는 거기를 아예 안 본다. 그래서
글을 고치고 그냥 커밋하면 빌드도 통과하고 배포도 성공하는데 **사이트에는 예전 내용이 그대로**
남는다.

pre-commit 훅으로 막았다. 중요한 건 **이 훅은 비밀번호가 필요 없다**는 점이다. 원문의 해시를
캐시에 적힌 해시와 대조하기만 한다.

```
비밀글 가드가 커밋을 멈췄다.

  · 원문이 바뀌었는데 재암호화하지 않았다: secret-01
    그대로 커밋하면 사이트에는 예전 내용이 남는다. → node scripts/secret.mjs
```

`content/secret/` 에 암호문 아닌 파일이 스테이징되는 것도 같이 잡는다. 발행된 글을 고쳐놓고
안 구운 건 차단하고, 아직 발행 안 한 새 원문은 초안일 수 있으니 경고만 한다.

## 남는 한계

솔직히 적어둘 것들이 있다.

**오프라인 무차별 대입에 노출된다.** 정적 호스팅이라 암호문을 누구에게나 내준다. 공격자가
자기 기계에서 무한정 PBKDF2 를 돌릴 수 있다. 60만 회로도 짧은 비밀번호는 못 지킨다.
단어 여러 개를 이은 긴 패스프레이즈여야 한다. 이건 설계로 없앨 수 있는 게 아니라 이 방식의
본질적 성질이다.

**이미 공개한 것은 돌아오지 않는다.** 나는 이미 커밋·푸시·배포까지 끝난 글 여섯 개를 비밀글로
옮겼는데, 그건 **앞으로의 노출만** 막는다. git 히스토리에 평문이 남아 있고 검색엔진이 이미
수집했을 수 있다. 히스토리까지 지우려면 `git filter-repo` 와 force push 가 필요하다.

**페이지를 내주는 서버를 신뢰한다는 전제가 깔린다.** 복호화 스크립트 자체가 그 서버에서 온다.
GitHub Pages 가 스크립트를 바꿔 내려주면 비밀번호를 가로챌 수 있다. [[secure-context]] 가
전송 중 변조는 막지만 출처가 바뀌는 건 못 막는다.

**본문 길이가 드러난다.** GCM 은 스트림 암호라 패딩이 없다. 암호문 길이가 평문 길이를
그대로 보여준다.

## 그래서

정적 사이트의 비밀글은 **"서버가 거절해준다" 가 아니라 "읽어도 못 읽는다"** 다. 둘은 전혀 다른
보장이다. 전자는 접근을 막고, 후자는 접근을 허용한 뒤 이해를 막는다.

그 차이를 알고 쓰면 쓸 만하다. 남에게 보이고 싶지 않은 작업 기록을, 배포 파이프라인을 건드리지
않고, 같은 저장소·같은 검색·같은 위키링크 안에 둘 수 있다.

모르고 쓰면 **암호문을 전 세계에 배포해놓고 짧은 비밀번호를 거는 일**이 된다.
